## Specs

### S1 — Independent weighted classifications and visible tags
User direction: “me gustaria que tuviese como porcentajes, porque hay problemas que pueden tener mas o menos componente de teoria de numeros por ejemplo.”
User clarification: “dos clasificaciones independientes sobre areas cognitivas y sobre areas matematicas. suman todas 1, usa porcentajes normalizados y para la ui pon solo el tag del porcentaje mas grande y del segundo si es que hay.”
Represent cognitive-area weights and mathematical-area weights independently per Problem; each populated axis is a normalized distribution summing to 1. The UI shows the highest-weight tag and the second-highest when present, within each axis. Do not seed an invented taxonomy or convert existing `TypeTag` rows without explicit mapping.
Checks: each populated axis accepts only normalized positive shares totaling exactly 1; math and cognitive sums validate separately; top-one/top-two display is ordered by share, and absent tags render as unclassified.

### S2 — Durable per-user problem progress and attempts
User direction: “lo demas ok, guardar los problemas resueltos y tal, para cada user.”
Record each authenticated user's progress per Problem and retain individual attempts. Supported outcomes are pending, solved, and given up; no progress row means not started. A retry creates a new attempt, while the per-problem status reflects the latest attempt. Keep progress private to its owner; do not expose it on public username pages. Anonymous picks may remain session-only.
Checks: authenticated outcomes persist across sessions; repeated attempts are retained; users cannot read or change another user's progress; pending/solved/given-up states and not-started fallback are truthful.

### S3 — Integer Elo per area, not global
User direction: “el elo esta dividido entre cada habilidad, no es uno general. es un entero, ya veré como se calculara.”
Store an integer Elo value per user and individual area tag; do not add one global rating or implement a calculation/update formula in this work. An absent rating row means no rating has been computed; do not invent an initial value.
Checks: one rating is unique per user/area tag, accepts integer values, and has no shared/global user rating field or implicit score seed.

### S4 — Ordered Problem hints
User direction: “tambien ya que estas crea el dato hint, un problema tiene una lista de hints de primera a ultima que debes leer queda claro?”
Store multiple hint text entries per Problem with explicit one-based order, unique within that Problem. This adds ordered hint data, not a per-user hint-view history or a hint/solution UI flow.
Checks: hints are returned in ascending order, order values cannot collide within one Problem, and separate Problems can each start their ordering at 1.

### S5 — Additive schema and local application
User authorization: “ok, pues pidele a un subagente que haga la migracion y la aplique a la db localm luego pusheas a main y mergeas a main”
The additive migration `MainApp/migrations/0005_learning_data_models.py` may be applied once to the verified local database. Do not seed taxonomy, Elo, hints, or progress, rewrite existing Problem rows, or apply migrations to remote/production databases. Inspect the database target and migration status first; stop if the target is not clearly local or unexpected migrations are pending.
Checks: `0005_learning_data_models` is applied to the intended local database, earlier migrations are unchanged, and existing data remains intact.
